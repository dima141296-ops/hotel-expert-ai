# Telegram-бот Hotel Expert AI

## Цель

Добавить локальный Telegram-интерфейс для подготовки экспертного контента об одном отеле. Бот проводит Дмитрия по вводу инспекционных данных, показывает сводку и запускает уже готовое AI-ядро только после явного подтверждения.

## Границы первой версии

Бот работает на Mac Дмитрия через long polling, пока запущена команда Python. Он доступен только пользователям из списка `TELEGRAM_ALLOWED_USER_IDS` и не публикует текст в каналы или социальные сети.

Данные диалога живут только в памяти. После перезапуска программы, отмены или успешной генерации пользователь начинает новую инспекцию. Постоянное хранение, загрузка JSON-файлов, вебхуки и работа нескольких пользователей одновременно остаются за пределами этого этапа.

## Конфигурация

Локальный `.env` содержит:

```text
TELEGRAM_BOT_TOKEN=<токен BotFather>
TELEGRAM_ALLOWED_USER_IDS=<ваш Telegram ID>
GEMINI_API_KEY=<локальный ключ>
GEMINI_MODEL=gemini-3.5-flash-lite
```

`.env.example` содержит только имена переменных без секретов. Чтобы дать доступ новому человеку, Дмитрий добавляет его числовой Telegram ID через запятую в `TELEGRAM_ALLOWED_USER_IDS` и перезапускает бота.

## Команды и доступ

- `/start` приветствует разрешённого пользователя и объясняет команду `/new`.
- `/new` запускает новый диалог инспекции, очищая предыдущие незавершённые данные.
- `/skip` пропускает текущее необязательное поле.
- `/cancel` отменяет диалог и удаляет его данные из памяти.

Каждое сообщение и нажатие кнопки проверяются по Telegram user ID. Неразрешённый пользователь получает короткое сообщение о закрытом доступе и не может начать диалог или вызвать Gemini.

## Диалог ввода

Бот запрашивает одно поле за раз. Текстовые списки вводятся по одному элементу на строку. Для необязательных списков и строк доступна `/skip`.

1. Название отеля — обязательно.
2. Город — необязательно.
3. Район — необязательно.
4. Дата инспекции — необязательно.
5. Подтверждённые факты — необязательно.
6. Личные наблюдения — необязательно.
7. Сильные стороны — необязательно.
8. Ограничения — необязательно.
9. Кому подходит — необязательно.
10. Снятые кадры — необязательно.
11. Вопросы для уточнения — необязательно.
12. Число номеров — необязательно; принимается только целое число.
13. Последняя реновация — необязательно.
14. Источники — необязательно.

После ввода бот создаёт `HotelData.from_dict(...)` и вызывает `validate()`. Если нет ни одного содержательного факта, наблюдения, сильной стороны, ограничения или снятого кадра, он объясняет это и возвращает пользователя к вводу подтверждённых фактов. Так бот использует те же правила, что и CLI.

## Подтверждение и генерация

Перед запросом к Gemini бот выводит краткую сводку: название, локацию, дату инспекции и количество фактов. Под сводкой находятся кнопки:

- `Создать контент` — запускает генерацию.
- `Начать заново` — очищает введённые данные и начинает с названия отеля.

При подтверждении бот создаёт `GeminiProvider` и передаёт его в существующий `ContentGenerator`. Синхронный вызов Gemini выполняется через `asyncio.to_thread`, чтобы не блокировать обработку обновлений Telegram.

`GeneratedContent.as_sections()` определяет пять отправляемых разделов. Каждый раздел отправляется отдельным сообщением. Если текст длиннее лимита Telegram в 4096 символов, он разбивается по границам строк. Последним сообщением бот напоминает проверить факты перед публикацией.

## Ошибки

- Нет `TELEGRAM_BOT_TOKEN` или список разрешённых ID пуст — программа завершается с понятным русским сообщением до запуска polling.
- Пользователь без доступа — получает сообщение о закрытом доступе; данные и AI-запрос не создаются.
- Пустое название отеля или неверное число номеров — бот повторно запрашивает это поле.
- Ошибки `HotelData`, `ContentGenerator` или Gemini показываются по-русски; диалоговые данные остаются доступными для повторной попытки.
- `/cancel` всегда завершает разговор без генерации.

## Архитектура

Новый модуль `app/telegram_bot.py` отвечает только за Telegram: проверку доступа, состояния диалога, кнопки, форматирование и отправку сообщений. Он использует существующие `HotelData`, `ContentGenerator`, `GeminiProvider` и `GeneratedContent`; правила валидации отеля и построения промпта не копируются.

Для пошагового диалога используется `python-telegram-bot` и `ConversationHandler`. Обновления обрабатываются последовательно, как рекомендует документация библиотеки для обработчиков с состоянием.

## Проверки

Автоматические тесты без сети проверяют:

- разбор списка разрешённых Telegram ID;
- отказ неразрешённому пользователю;
- преобразование текстовых ответов в словарь для `HotelData`;
- обработку `/skip`, `/cancel` и неверного числа номеров;
- проверку обязательных данных перед подтверждением;
- разбиение длинного сообщения под лимит Telegram;
- передачу готового результата из замоканного `ContentGenerator` в пять сообщений.

Ручная приёмка: Дмитрий запускает бота, отправляет `/new`, вводит данные одного отеля, проверяет сводку, подтверждает генерацию и получает пять разделов. Затем `/cancel` и доступ с другого аккаунта проверяются без обращения к Gemini.
